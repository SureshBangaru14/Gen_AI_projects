		- Reranking is the second-stage retrieval process in a RAG system where initially retrieved documents/chunks are evaluated again using a more powerful ranking model to identify the most relevant results.

What is Reranking? : 

	Definition :

		- Reranking is the process of taking an initial set of retrieved documents/chunks and reordering them according to their relevance to the user's query.
		
		- The first retrieval stage is normally optimized for speed and recall.

		- The reranking stage is optimized for relevance and precision.
		
		
Why Reranking is Needed :

	Vector search is very useful, but the initial similarity score does not always perfectly represent relevance.

	For example:

		Query:
		"What is the employee's maternity leave duration?"

		Vector search might return:

		1. Employee Leave Policy
		2. Annual Leave
		3. Employee Benefits
		4. Maternity Leave
		5. Insurance Benefits

		The actual answer may be in:

			4. Maternity Leave
			
	- because the embedding similarity between the query and another general "leave" document may be higher.

	- Reranking provides a second opportunity to evaluate the candidates.
	
	
	
Retrieval vs Reranking : 


	Retrieval and Reranking are two different stages in a search/RAG pipeline.

		| Feature                     | Retrieval                              | Reranking                              |
		|-----------------------------|----------------------------------------|----------------------------------------|
		| Purpose                     | Find candidate documents               | Order candidate documents              |
		| Stage                       | First stage                            | Second stage                           |
		| Main Goal                  | Recall                                 | Precision                              |
		| Input                      | Query + Database                       | Query + Retrieved Candidates           |
		| Number of Documents        | Large                                  | Smaller                                |
		| Speed                      | Faster                                 | Slower                                 |
		| Model                       | Embedding / BM25                       | Cross-Encoder / Reranker / LLM         |
		| Database Search             | Yes                                    | Usually No                             |
		| Query-Document Interaction  | Limited                                | Stronger                               |
		| Processing                  | Broad Search                           | Deep Relevance Analysis                |
		| Output                      | Candidate Documents                    | Ordered/Reranked Documents              |
		| Typical Top-K               | Top-50 / Top-100 / Top-200             | Top-5 / Top-10 / Top-20                |
		| Focus                       | Find relevant documents                | Put the most relevant first             |
		| Computational Cost          | Lower                                  | Higher                                  |
		| Accuracy                    | Good initial recall                    | Higher final precision                 |
		| Example                     | FAISS / ChromaDB / BM25                | Cross-Encoder / Cohere Reranker / LLM  |

The 7 concepts in one line :

	1. What is Reranking?
	   → Reorder retrieved results by relevance.

	2. Why is it needed?
	   → Initial retrieval is not always perfectly relevant.

	3. Retrieval vs Reranking
	   → Retrieval finds candidates; reranking orders them.

	4. First Stage Retrieval
	   → Quickly retrieves a larger candidate set.

	5. Second Stage Ranking
	   → Deeply evaluates and scores those candidates.

	6. Precision Improvement
	   → Moves the most relevant documents to the top.

	7. Context Quality Improvement
	   → Sends cleaner, more relevant context to the LLM.
	   
	   
1. Top-K Retrieval :

	What is Top-K?

		Top-K retrieval means selecting the K highest-scoring documents from the retrieval results.

		Here, K represents the number of documents/chunks you want to retrieve.

		For example:

			K = 5
			
2. Relevance Score :

	What is a Relevance Score?

		A relevance score represents how strongly a document is considered relevant to the query.

		For example:

		Query:
		"What is the refund policy?"

		Possible scores:

		Document A → 0.96
		Document B → 0.83
		Document C → 0.61
		Document D → 0.22

		Higher score generally means:

		Higher relevance

		But an important point is:

			The meaning and scale of a relevance score depend on the model and retrieval system.

		A score of 0.90 from one system cannot automatically be compared with 0.90 from another system.


3. Similarity Score :

	What is Similarity Score?

		A similarity score measures how similar two representations are, commonly:

		Query
		   ↕
		Document

		In vector retrieval, the query and document are converted into embeddings.
		
		
	Cosine Similarity :
	
		Cosine Similarity =
		A · B
		-------
		|A| |B|

		Typically:

			-1 → opposite direction
			 0 → unrelated/orthogonal
			+1 → same direction
			
	Dot Product :
	
		Score = A · B
		
	Euclidean Distance :

		Unlike similarity, distance generally means:

		Smaller distance
		      ↓
		More similar
		

4. Ranking Function :

	What is a Ranking Function?

		A ranking function determines the order of documents based on their scores or features.

		Simple ranking:

			Score
			  ↓
			Sort descending
			  ↓
			Highest score first

			Example:

			A → 0.92
			B → 0.87
			C → 0.74
			D → 0.51
			
			
		More Advanced Ranking :

			A ranking function can combine multiple signals.

			For example:

				Final Score =
				
					0.60 × Vector Score
					+
					0.25 × BM25 Score
					+
					0.15 × Metadata Score

			Example:

				Vector Score = 0.90
				BM25 Score   = 0.80
				Metadata     = 1.00

				Then:

				Final Score =
				(0.60 × 0.90)
				+
				(0.25 × 0.80)
				+
				(0.15 × 1.00)

				= 0.54 + 0.20 + 0.15

				= 0.89

				This allows a system to combine multiple retrieval signals.
				
				
				In a reranking system :

					A cross-encoder might calculate:

						Query + Document
						       ↓
						Reranker Model
						       ↓
						Relevance Score
						       ↓
						   Sort
						       ↓
						   Top-N
						   
						   
						   
5. Score Normalization :

		Different scoring systems can produce scores on different scales.

		For example:

		Vector Search:
		0.0 → 1.0

		BM25:
			0 → 25

		Another model:
			-5 → +5

		It is difficult to combine these directly.

		Therefore, we may need score normalization.
		
		
		Min-Max Normalization :

				One common technique is:

				Normalized Score =
							Score - Minimum Score
							---------------------
							Maximum Score - Minimum Score

				Example:

					Scores:

					10
					20
					30
					40
					50

					Minimum:

						10

					Maximum:

						50

					For score 30:

						(30 - 10) / (50 - 10)

						= 20 / 40

						= 0.5
						
					So:

						Original     Normalized

						10              0.00
						20              0.25
						30              0.50
						40              0.75
						50              1.00
						
						
		Why normalization matters :

				Suppose you want hybrid retrieval:

					Dense Search
					      +
					BM25
					      ↓
					Combined Score

				But:

					Dense = 0.85
					BM25  = 18.5

				Adding them directly:

					0.85 + 18.5

				would allow the BM25 scale to dominate.

					After normalization:

						Dense → 0.85
						BM25  → 0.78

				Now you can combine them more meaningfully.

					For example:

					Final Score =
						0.7 × Dense Score
						+
						0.3 × BM25 Score
						
						
						
						
6. Threshold Filtering :


		What is Threshold Filtering?

			Threshold filtering removes documents whose score is below a predefined minimum.

			Example:

				Threshold = 0.70

			Retrieved:

				Document A → 0.94
				Document B → 0.88
				Document C → 0.76
				Document D → 0.61
				Document E → 0.42

			Apply:

				score >= 0.70

			Result:

				Document A → 0.94
				Document B → 0.88
				Document C → 0.76

			Remove:

				Document D → 0.61
				Document E → 0.42
				
				
				
		Top-K vs Threshold :

			These are different concepts.

			Top-K

				Always attempts to return up to K results.

			Top-K = 5

				Even if the scores are:

				0.91
				0.82
				0.61
				0.42
				0.21

			you may still receive five results.

			Threshold

				Returns only results above a minimum score.

				Threshold = 0.70

				Result:

				0.91 ✓
				0.82 ✓
				0.61 ✗
				0.42 ✗
				0.21 ✗
				
				
Concept              Simple Meaning
---------------------------------------------------------------
Top-K Retrieval      Retrieve the K highest-ranked candidates
Relevance Score      How relevant a document is to the query
Similarity Score     How similar the query and document representations are
Ranking Function     Determines the order of candidates
Score Normalization  Converts scores to a comparable scale
Threshold Filtering  Removes results below a minimum score


3. Reranking Architectures :

		Reranking architectures describe how a query and document are compared and how their relevance is calculated.

		The three important architectures are:

		1. Bi-Encoder
		2. Cross-Encoder
		3. Hybrid Ranking

		A useful way to understand them is:

				    Reranking Architectures
				            │
			  ┌─────────────────┼─────────────────┐
			  │                 │                 │
			  ▼              	      ▼                        ▼
		     Bi-Encoder       Cross-Encoder      Hybrid Ranking
			  │                 │                 │
		     Fast retrieval      High accuracy    Multiple signals
			  │                 │                 │
		     Separate vectors   Query + Document   Keyword + Semantic
		     
		 The key distinction to remember :

				Bi-Encoder: encode query and documents separately → compare vectors → fast retrieval.

				Cross-Encoder: process query and document together → model directly evaluates their interaction → slower but useful for high-quality reranking.

				Hybrid Ranking: combine keyword and semantic signals → normalize/weight them → produce a combined ranking.
						     
		     
1. Bi-Encoder :

		A Bi-Encoder uses two encoding operations:

		Query
		  ↓
		Query Encoder
		  ↓
		Query Vector

		Document
		  ↓
		Document Encoder
		  ↓
		Document Vector

		Query Vector + Document Vector
			      ↓
		       Vector Similarity
			      ↓
			  Score

		The query and document are encoded independently.
		
		Bi-Encoder is primarily your first-stage retriever.
		
		
		1.1 What is a Bi-Encoder?

			A Bi-Encoder independently converts the query and documents into vectors.

					 Query
					   │
					   ▼
				    Query Encoder
					   │
					   ▼
				     Query Vector
					   │
					   │
					   ▼
				      Similarity
					   ▲
					   │
					   │
				   Document Vector
					   ▲
					   │
				  Document Encoder
					    ▲
					   │
				       Document

			The important word is independently.

			Query    → Encoder → Query Vector

			Document → Encoder → Document Vector
			
			Then:

				Query Vector
				      +
				Document Vector
				      ↓
				Cosine Similarity
				      ↓
				Similarity Score


2. Cross-Encoder :

		Now we move to the second technique.

		2.1 What is Cross-Encoder?

			A Cross-Encoder receives:

				Query + Document

				together.

				Query
				  +
				Document
				  ↓
				Cross-Encoder
				  ↓
				Relevance Score

				This is fundamentally different from a Bi-Encoder.


		2.2 Bi-Encoder vs Cross-Encoder :
		
			Bi-Encoder :
			
				Query ──────→ Encoder ──────→ Vector
								  │
								  ▼
							      Similarity
								  ▲
								  │
				Document ───→ Encoder ──────→ Vector
				
			Cross-Encoder :
			
			Query ──────┐
				    │
				      ▼
			       Cross-Encoder
				      ▲
				    │
			Document ───┘
				    │
				    ▼
			      Relevance Score
			      
			      
		2.3 Query + Document Pair :

			For our query:

			How many weeks of maternity leave are provided?

			and document:

			Employees are eligible for 26 weeks of maternity leave.

			the pair is:

			(
			    "How many weeks of maternity leave are provided?",
			    "Employees are eligible for 26 weeks of maternity leave."
			)

			The Cross-Encoder evaluates that pair.
			
			
3. Hybrid Ranking :

		Now we combine:

			Keyword Search
			       +
			Semantic Search
			       ↓
			Combined Ranking

			This is useful because keyword and semantic retrieval have different strengths.
			
			
		3.1 Keyword Search :

			Keyword search focuses on exact terms.

			For example:

			Query:

			"maternity leave 26 weeks"

			A keyword system can strongly match:

			"Employees are eligible for 26 weeks of maternity leave."

			because it contains:

			maternity
			leave
			26
			weeks

			A common algorithm is:

				BM25
				
		3.2 Semantic Search :

			Semantic search doesn't require exact wording.

			Query:

				"How long can a mother take leave?"

			Document:

				"Employees are eligible for 26 weeks of maternity leave."

			Even though the wording is different, embeddings can identify semantic similarity.

			Query
			 ↓
			Embedding
			 ↓
			Vector DB
			 ↓
			Semantic Score
			
			
		3.3 Hybrid Ranking Architecture :


				         QUERY
				           │
			      ┌────────────┴────────────┐
			      │                         │
			         ▼                                    ▼
			  BM25 Search             Vector Search
			      │                         │
			         ▼                                    ▼
			Keyword Score             Semantic Score
			      │                         │
			      └────────────┬────────────┘
				                ▼
				    Score Normalization
				           │
				                ▼
				    Combined Score
				           │
				                ▼
				        Ranking
				           │
				                ▼
				         Top-K
				           │
				                ▼
				    Cross-Encoder
				           │
				                ▼
				         Top-N
				           │
				                ▼
				          LLM
				          
				          
		3.4 Hybrid Ranking Formula :

			For example:

			Combined Score
			=
			0.4 × Keyword Score
			+
			0.6 × Semantic Score

			The weights are configurable.

			KEYWORD_WEIGHT = 0.4
			SEMANTIC_WEIGHT = 0.6

Optimization :

	Definition :

		- RAG optimization is the process of improving the retrieval,
		  reranking, model inference, caching, and LLM stages so that
		  the system becomes faster, more efficient, scalable, and
		  cost-effective.

		- The main goals of RAG optimization are:

			1. Reduce latency
			2. Increase throughput
			3. Reduce memory usage
			4. Avoid repeated computation
			5. Reduce LLM/API cost

		- In this section, we use five important optimization techniques:

			1. Latency Reduction
			2. Batch Reranking
			3. Model Quantization
			4. Cache Results
			5. Cost Optimization


RAG Optimization Flow :

		User Query
		     ↓
		Query Embedding
		     ↓
		ChromaDB
		     ↓
		Top-K Retrieval
		     ↓
		Batch Reranking
		     ↓
		Quantized Reranker
		     ↓
		Top-N Results
		     ↓
		Cache
		     ↓
		LLM / Qwen
		     ↓
		Final Answer


1. Latency Reduction :

	Definition :

		- Latency is the amount of time required by the RAG system
		  to process a user query and return the final answer.

		- Lower latency means the user receives the answer faster.

		- In RAG, one important source of latency is the reranking
		  stage because the reranker must evaluate multiple
		  query-document pairs.

	Example :

		Query
		  ↓
		ChromaDB
		  ↓
		Top 100
		  ↓
		Reranker
		  ↓
		Top 5

		Here the reranker processes 100 candidates.

	Optimized :

		Query
		  ↓
		ChromaDB
		  ↓
		Top 20
		  ↓
		Reranker
		  ↓
		Top 5

		Now the reranker processes only 20 candidates.

	Code :

		TOP_K = 20

		- TOP_K controls how many candidates are retrieved from
		  the first-stage vector database.

		- Lower TOP_K can reduce reranking latency.

		- However, reducing TOP_K too much can reduce recall because
		  the relevant document may not be retrieved.

		Trade-off :

		Lower TOP_K
		     ↓
		Lower latency
		     ↓
		Possibly lower recall


2. Batch Reranking :

	Definition :

		- Batch reranking means processing multiple query-document
		  pairs together instead of processing each document
		  individually.

	Without Batch :

		Query + Document 1 → Reranker
		Query + Document 2 → Reranker
		Query + Document 3 → Reranker
		Query + Document 4 → Reranker
		...
		Query + Document 20 → Reranker

	With Batch :

		Query
		  ↓
		┌─────────────────────┐
		│ Document 1          │
		│ Document 2          │
		│ Document 3          │
		│ ...                 │
		│ Document 16         │
		└─────────────────────┘
		  ↓
		Reranker
		  ↓
		Scores

	Code :

		RERANK_BATCH_SIZE = 16

		scores = reranker.predict(
			pairs,
			batch_size=RERANK_BATCH_SIZE
		)

		- The batch size determines how many query-document pairs
		  are processed together.

	Example :

		TOP_K = 50
		BATCH_SIZE = 16

		Processing becomes approximately:

			Batch 1 → 16 documents
			Batch 2 → 16 documents
			Batch 3 → 16 documents
			Batch 4 → 2 documents

	Benefits :

		- Better GPU utilization
		- Higher inference throughput
		- Fewer individual inference operations
		- Useful when reranking many candidates

	Trade-off :

		Larger batch size
		     ↓
		More memory required

	Smaller batch size
		     ↓
		Lower memory usage
		     ↓
		Possibly lower throughput


3. Model Quantization :

	Definition :

		- Model quantization is the process of representing model
		  parameters using lower numerical precision.

		- It is mainly used to reduce model memory requirements
		  and potentially improve inference efficiency.

	Common Precision :

		FP32
		  ↓
		FP16
		  ↓
		INT8
		  ↓
		INT4

	Example :

		FP32
		32-bit representation

		FP16
		16-bit representation

		INT8
		8-bit representation

		INT4
		4-bit representation

	Code :

		quantization_config = BitsAndBytesConfig(
			load_in_8bit=True
		)

		model = AutoModelForSequenceClassification.from_pretrained(
			model_name,
			quantization_config=quantization_config,
			device_map="auto"
		)

		- load_in_8bit=True tells the supported model-loading
		  stack to load the model using 8-bit quantization.

	Benefits :

		- Lower memory requirement
		- Can allow larger models to fit on available hardware
		- May improve inference efficiency depending on hardware
		  and runtime

	Trade-off :

		Lower precision
		     ↓
		Lower memory
		     ↓
		Potential efficiency improvement
		     ↓
		Possible quality/accuracy change

		Therefore, quantized and non-quantized models should be
		benchmarked on the actual RAG evaluation dataset.


4. Cache Results :

	Definition :

		- Caching means storing previously calculated results so
		  that the system does not have to perform the same
		  computation again.

	Without Cache :

		Query 1
		  ↓
		Embedding
		  ↓
		ChromaDB
		  ↓
		Reranker
		  ↓
		LLM
		  ↓
		Answer

		Same Query 2
		  ↓
		Embedding
		  ↓
		ChromaDB
		  ↓
		Reranker
		  ↓
		LLM
		  ↓
		Same Answer

	With Cache :

		Query 1
		  ↓
		Embedding
		  ↓
		ChromaDB
		  ↓
		Reranker
		  ↓
		LLM
		  ↓
		Answer
		  ↓
		Cache

		Same Query 2
		  ↓
		Cache HIT
		  ↓
		Return previous result

	Code :

		@lru_cache(maxsize=1000)
		def ask(query):
			...

		- maxsize=1000 means the local cache can retain up to
		  approximately 1000 distinct argument combinations.

	Cache Flow :

		Query
		  ↓
		Cache?
		  │
		  ├── YES → Return cached result
		  │
		  └── NO
		       ↓
		    RAG Pipeline
		       ↓
		    Store Result
		       ↓
		    Return Answer

	Benefits :

		- Avoids repeated embedding
		- Avoids repeated vector search
		- Avoids repeated reranking
		- Avoids repeated LLM generation
		- Reduces latency
		- Can reduce API/LLM cost

	Production :

		- Python lru_cache is suitable for a simple single-process
		  example.

		- Distributed applications generally use a shared cache
		  such as Redis.

		- Cache invalidation is important when the underlying
		  documents or permissions change.


5. Cost Optimization :

	Definition :

		- Cost optimization means reducing the amount of expensive
		  computation and paid model usage while maintaining
		  acceptable answer quality.

		- In RAG, the LLM is often one of the more expensive stages,
		  especially when using paid APIs.

	Without Optimization :

		ChromaDB
		     ↓
		Top 20
		     ↓
		Reranker
		     ↓
		20 Documents
		     ↓
		LLM
		     ↓
		Many Input Tokens

	Optimized :

		ChromaDB
		     ↓
		Top 20
		     ↓
		Reranker
		     ↓
		Top 3
		     ↓
		LLM
		     ↓
		Fewer Input Tokens

	Code :

		TOP_N = 3

		- TOP_N controls how many reranked documents are finally
		  passed to the LLM.

	Example :

		TOP_K = 20

		ChromaDB retrieves:

			20 candidates

		Reranker evaluates:

			20 candidates

		Reranker selects:

			Top 3

		LLM receives:

			3 chunks

	Benefits :

		- Fewer input tokens
		- Smaller context
		- Lower LLM processing
		- Potentially lower API cost
		- Less irrelevant information in the prompt


Complete Optimization Example :

		TOP_K = 20

		RERANK_BATCH_SIZE = 16

		TOP_N = 3

		quantization_config = BitsAndBytesConfig(
			load_in_8bit=True
		)

		@lru_cache(maxsize=1000)
		def ask(query):
			...


Complete RAG Optimization Flow :

		User Query
		     ↓
		Query Embedding
		     ↓
		ChromaDB
		     ↓
		TOP_K = 20
		     │
		     └── Latency Reduction
		     ↓
		20 Candidates
		     ↓
		Batch Reranking
		     │
		     └── Batch Size = 16
		     ↓
		Quantized Reranker
		     │
		     └── INT8
		     ↓
		Reranked Candidates
		     ↓
		TOP_N = 3
		     │
		     └── Cost Optimization
		     ↓
		3 Relevant Chunks
		     ↓
		Cache Check
		     │
		     ├── Cache HIT
		     │      ↓
		     │   Return Result
		     │
		     └── Cache MISS
		            ↓
		         Qwen / LLM
		            ↓
		         Answer
		            ↓
		         Cache Result


Optimization Summary :

	1. Latency Reduction :

		TOP_K = 20

		- Limits the number of candidates processed by the
		  expensive reranking stage.

	2. Batch Reranking :

		RERANK_BATCH_SIZE = 16

		- Processes multiple query-document pairs together.

	3. Model Quantization :

		load_in_8bit=True

		- Reduces model memory requirements using lower precision.

	4. Cache Results :

		@lru_cache(maxsize=1000)

		- Avoids repeating the same RAG computation for cached queries.

	5. Cost Optimization :

		TOP_N = 3

		- Sends only the most relevant reranked chunks to the LLM.


Easy Interview Explanation :

		"First, I reduce latency by limiting the number of
		candidates retrieved from the vector database.

		Then I use batch reranking to process multiple
		query-document pairs efficiently.

		I use model quantization to reduce reranker memory
		requirements.

		I cache repeated queries to avoid unnecessary
		recomputation.

		Finally, I reduce LLM cost by sending only the top
		relevant chunks to the generation model."


Key Formula :

		First Stage :

			Large Document Collection
			        ↓
			     Vector DB
			        ↓
			      TOP-K


		Second Stage :

			TOP-K Candidates
			        ↓
			    Reranker
			        ↓
			      TOP-N


		Generation :

			TOP-N Chunks
			        ↓
			       LLM
			        ↓
			     Answer


Core Principle :

		Recall First
		     ↓
		Retrieve enough candidates

		Precision Second
		     ↓
		Rerank candidates

		Efficiency Third
		     ↓
		Optimize latency, memory, cache, and cost

		Generation Last
		     ↓
		Send only the most relevant context to the LLM
